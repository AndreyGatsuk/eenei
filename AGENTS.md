The theme must work for anyone who just installs it.
Never change editor settings to get an effect.
Design for the syntax grammar only.

Run commands from the repository root: `npm ci`, `npm run dev`, `npm run check`, `npm run screenshots`, `npm run package`.

Palette families are in src/palettes/. The compiler combines each family with dark/light base roles and shared status colors. Never edit generated vscode/themes files or the contributes.themes list manually; npm run build regenerates them.

README screenshots: `npm run screenshots`. scripts/render.js tokenizes assets/previews/example.py using VS Code grammars and writes the shared Python comparison to assets/previews/ with headless Chrome. Set CHROME_BIN if Chrome is not on the default path. VSCODE_EXTENSIONS_DIR can point to a local VS Code extensions directory for offline grammar checks and screenshots.

The theme is named Eenei, with on Rose, on Dahlia, on Lilac and on Hellebore families. All families share blue and define string and comment colors individually. The extension ID is AndreyGatsuk.eenei, publisher is AndreyGatsuk, and repository is https://github.com/AndreyGatsuk/eenei. Eenei is a separate extension from Navigate. Do not publish a release as part of a source refactor.

Release: bump version in vscode/package.json, merge, then push tag v<version> on main. .github/workflows/publish.yml publishes to the Marketplace with vsce publish --oidc and to Open VSX with ovsx publish --trusted-publishing, no tokens.

README palette tables and assets/palettes PNG strips are generated by scripts/documentation.js during npm run build. Detailed guides live in docs/. Packaging stages docs and assets under vscode/ and writes only dist/eenei.vsix. Report implementation and pinned inventories live in scripts/coverage/.

Checks and render commands prepare pinned VS Code grammars in .cache/grammars/<revision>/ before starting workers. Test workers only read cached files; do not add per-worker downloads. VSCODE_EXTENSIONS_DIR explicitly selects installed grammars instead.

Keep one repository for shared palettes and editor ports. VS Code lives in vscode/; add zed/ or nvim/ only when implementing those ports. Do not advertise an unimplemented port.
